# DriveQuest2

하루 운행을 마친 뒤 주차 상태에서 회전 영상을 돌아보는 Android / Pleos Connect UI 프로토타입.
기존 DriveQuest와 다른 폴더·applicationId를 사용하며 기존 앱과 데이터를 변경하지 않는다.

## 화면

- 인사: 밝은 베이지 바탕, 초록 그라데이션 문장이 떠오른 뒤 자동으로 첫 탭 진입. 버튼 없음. 첫 탭 구성요소 순차 페이드인.
- 오늘의 주행: 좌회전 / 우회전 / 유턴 / 커브 각 8회·9회·2회·5회, 시간순 24개 영상.
- 영상: 전면 시점으로 움직이는 합성 도로, 초록 실선 추천 경로와 주황 점선 주행 경로 동시 표시. 재생·일시정지·처음으로·탐색.
- 내 주행실력: 회전 종류별 누적 정확도, 과속·신호 준수·횡단보도 정지선 침범 횟수.
- 도전과제: 자체 그린 아이콘과 진행 막대를 가진 10개 카드, 4열.
- 오전 08–09시, 점심 12–13:30, 저녁 18–19시. 요청의 ‘12am’은 점심이라는 문맥에 따라 정오로 해석.

## 구현과 데이터 범위

현재 화면 수치는 `domain/ReviewData.kt`의 고정 기획 데이터이며 실제 센서, 영상 인식, 개인 주행 기록 또는 안전성 평가 결과가 아니다. `scripts/generate-videos.py`가 만든 24개 960×540 / 20fps / 10초 MP4는 실제 카메라 촬영이 아닌 독자적인 절차적 3D 투영 영상이다. 두 경로도 미리 작성한 가상 궤적이며 실제 도로에서 검증된 최적 경로가 아니다. UI는 사용자 요청에 따라 짧은 제품 문구만 사용하고 이 범위는 문서에 기록한다.

차량 전면 카메라 연동, 하루 기록 수집·영구 저장, 실도로 최적 경로 계산, 교통신호·정지선 판정, 실제 정확도 분석은 미구현이다. 영상 수집이나 개인정보 업로드는 하지 않는다. GitHub 업로드나 공모전 제출은 수행하지 않았다.

AAOS에서는 실제 CarUxRestrictions가 unknown/restricted이면 화면을 차단한다. 앱 비활성화와 제한 전환 시 동영상 재생을 멈춘다. 일반 Android에서는 정차 상태 검증을 주장하지 않는다. 제한 상태를 주입한 UI 테스트는 실제 Car 서비스 전환 검증이 아니다.

## 빌드와 실행

Kotlin 2.0.0 / AGP 8.8.2 / Gradle 8.10.2 / JDK 17 / API 35 / minSdk 28 / Vehicle dependency 2.3.2.
기존 DriveQuest의 로컬 SDK/JDK/Gradle 캐시를 재사용한다. 다른 PC에서는 `scripts/build.sh`의 DRIVEQUEST2_JDK / DRIVEQUEST2_SDK / DRIVEQUEST2_GRADLE_CACHE 환경변수를 설정하고 local.properties의 SDK 위치를 지정한다. 키·캐시는 복사하지 않았다.

```bash
./scripts/build.sh assembleDebug testDebugUnitTest lintDebug
./scripts/build.sh connectedDebugAndroidTest
# 기존 Pleos GUI가 실행 중이어야 한다.
../DriveQuest/.local/android-sdk/platform-tools/adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk
../DriveQuest/.local/android-sdk/platform-tools/adb -s emulator-5554 shell am start -n io.drivequest2.app.debug/io.drivequest2.app.MainActivity
```

패키지: `io.drivequest2.app.debug`. 앱 표시명: DriveQuest2. 현재 산출물은 UI 확인용 debug APK이며 제출용 서명 release가 아니다.

## 0.2 요약과 월별 기록

첫 탭에 A- 등급·한줄평·두 개선 포인트를 담은 요약 카드를 추가했다. 회전별 횟수 카드 오른쪽은 정확도, 각 영상 행 오른쪽은 옅은 정확도 퍼센트를 표시한다. 두 번째 탭 상단에 이번달 주행 기록을 추가했다. 11월 1–14일에 각 한 개의 소수 점수를 표시하며 축은 E/D/C/B/A, 날짜 라벨은 11/1·11/8이다. +/- 축 라벨 없이 점의 높이로 세부 차이를 나타낸다. 오른쪽 피드백 다섯 줄은 사용자가 지정한 콘셉트 문구다. 야간 정확도 비교·지난달 대비 향상 등의 실제 측정 또는 모집단 분석은 수행하지 않았다.

2026-11-14: 0.2.0-monthly-review (2), assembleDebug / testDebugUnitTest / lintDebug / connectedDebugAndroidTest 성공. 단위 4개·UI 2개 통과. 자동 진입, 요약, 그래프, 하단 과제 스크롤, 제한 전환 시 영상 제거를 검증했다. 화면 및 인트로 녹화: artifacts/v02/.

## 0.2.1 월간 정확도와 변동 그래프

첫 탭 영상 목록 위에 ‘영상으로 돌아보기’를 추가했다. 오늘의 정확도는 좌회전 88%, 우회전 91%, 유턴 82%, 커브 94%. 월별 정확도는 별도 필드로 좌회전 85%, 우회전 89%, 유턴 78%, 커브 90%를 표시한다. 두 번째 탭에도 그래프·정확도·통계·도전과제 순서의 페이드인과 작은 상승 이동을 적용했다.

그래프는 콘셉트 날짜 11/1–11/15의 일별 15개 점을 사용하고 C(2.0)–A+(4.3) 사이를 반복해서 오르내린다. 축 문자는 E/D/C/B/A를 유지하며 A 위 여백에 A+ 수준 점을 배치한다. 날짜 라벨은 11/1, 11/8, 11/15이다. 오른쪽 피드백을 ‘정지선 침범은 주의가 필요해보입니다’로 변경했다. 모든 수치와 비교 문구는 기획용 고정 값이다.

첫 인사말은 42sp Bold로 굵기를 높였으며 그라데이션·등장 시간은 유지한다.

## 0.3 영상 24개와 도로 장면 개선

요약 제목은 ‘오늘 주행 요약’. 좌회전 8회, 우회전 9회, 유턴 2회, 커브 5회로 이벤트 목록과 영상 개수를 일치시켰다. 영상 생성기는 Kotlin 이벤트 카탈로그를 직접 읽으므로 별도 목록의 불일치를 방지한다. 오전·점심·저녁 각 8개이며 모두 시간순이다.

독립 도로 중심 좌표를 기준으로 좌우 경계를 -5m/+5m, 가운데 구분선을 0m에 배치한다. 카메라와 추천 궤적은 우측 차로 +2.4m, 주행 궤적은 그 근처의 작은 변위다. 모든 도로 표본에서 구분선이 두 경계의 중점인지 검증한다. 우측 차로 카메라에서는 도로 중앙선이 화면의 왼쪽에 보이는 것이 정상이며 화면 중앙과 도로 중앙을 혼동하지 않는다.

나무·초록 차량 신호등·가드레일을 월드 좌표에 배치하고 깊이순으로 그렸다. 기존 주택·아침/낮/저녁 조명을 유지했다. 카메라 위치·방향은 보간하여 움직임을 부드럽게 하고 영상은 20fps로 생성했다. 32개 사전 미리보기와 최종 인코딩 프레임을 검토했으며 24개 전체 디코딩·10초 길이·썸네일 대응을 검사했다. 합성 신호등은 도로 상황 판단이나 실제 신호 준수 측정이 아니다.

최신 검증과 영상 해시는 docs/validation/RESULTS.json, VIDEOS.json을 따른다. 실제 캡처는 artifacts/v03/, 영상 검토 모음은 artifacts/road-review/에 보관한다.

## 0.3.1 교차로 영상과 플레이어

좌회전 8개·우회전 9개는 독립적인 직교 4거리 도로에서 90도 회전한다. 유턴 2개·커브 5개와 합쳐 총 24개이며 이벤트 카탈로그와 raw MP4가 일대일 대응한다. 모든 차량 신호등은 차도 위 가로형 지지대에 매달린 형태로 변경했다. 집·나무·가드레일과 시간대 조명은 유지했다.

영상 오른쪽 위 검은 사각형의 흰 ×로 닫는다. 작은 시각 요소의 터치 영역은 48dp로 확보했다. 아래 범례는 초록 실선 ‘최적 경로’, 주황 점선 ‘주행 경로’다. ‘최적 경로’는 콘셉트 화면의 명칭이며 실제 교통·장애물·차량 동역학을 고려한 최적화 결과가 아니다. 영상은 합성 장면이다.

24개 파일 전체 ffmpeg 디코딩 통과. 종류별 개수와 검사 내역은 artifacts/v031/videos.json. UI 테스트는 전체 24개 행 스크롤 접근, 각각 10초 미디어 리소스, 범례 표시와 × 닫기를 검사한다.

2026-11-14 검증: assembleDebug / testDebugUnitTest(4개) / lintDebug / connectedDebugAndroidTest(3개) 통과. 기기 종료와 재부팅 직후 대기를 해소한 후 최종 전체 검증을 완료했다.

## 유턴 영상과 목록 스크롤 보완

유턴 ev05(08:31), ev20(18:29)는 도로 자체가 U자로 휘는 장면 대신, 직선 양방향 도로의 점선 중앙선을 횡단해 반대편 차로로 진입하는 합성 장면이다. 유턴 구간은 노란 점선, 나머지 구간은 실선 중앙선이며 양 방향 화살표를 추가했다. 실제 도로 유턴 허용 여부를 판정하는 기능은 아니다. 두 MP4 전체 디코딩 통과. 영상 목록의 직접 스크롤 이동량은 50%, 손을 놓은 뒤 초기 관성 속도는 35%로 조정했다.

오늘 주행 요약의 유턴 피드백은 ‘유턴 시 더 작게 돌 필요가 있습니다’, 월별 평가는 ‘유턴 시 더 작게 도는 습관이 필요합니다’로 변경했다. 영상 목록 직접 이동량은 기본의 10%, 초기 관성 속도는 기본의 5%로 추가 감소했다. 고정 콘셉트 피드백이며 실제 운전자 판단 결과가 아니다.

횡단보도 정지선 침범 통계 아이콘은 우측을 향한 측면 자동차의 오른쪽 절반과 앞바퀴 왼쪽 작은 정지선으로 변경했다. 과제 아이콘은 별도로 유지한다. 영상 목록의 직접 스크롤은 기본 이동량 4%, 초기 관성 속도 1%로 추가 감소했다.

## DriveQuest2 소개 영상·문서

DriveQuest1 원본은 수정하지 않고 submission/output과 submission/templates에 새로 제작했다. 2분 21초 1080p/30fps 무음 영상은 질문 카드·설명·최신 앱 녹화로 구성한다. 질문은 ‘영상으로 나의 운전을 교정할 수 있다면?’이다. 웰컴·재생·월간 화면을 최신 debug APK에서 재촬영했으며, 유턴은 선명한 보라색(#922BEE), 커브는 연두색(#80BA28)으로 표시한다. 녹화와 APK의 대응은 submission/output/CAPTURE_MANIFEST.json에 기록했다. 참가자 실명은 공개 영상·소개서에 넣지 않았다. 공식 접수양식의 개인정보·개별 동의·서명은 미작성이다. 이 묶음은 영상·문서 준비본이며 제출용 release APK나 GitHub 공개·이메일 접수 완료를 뜻하지 않는다. 생성 도구: scripts/create-submission-docs.py, scripts/capture-product-film.py, scripts/render-product-film.py.
